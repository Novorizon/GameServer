# 可选轻量包加密

默认模式 `AesGcm`：`28 字节明文头 + 等长密文负载 + 16 字节验证标签`。没有证书、HTTP 升级、TLS 协商或自动降级。轻量是指连接流程和状态简单，算法采用标准 AES-256-GCM。

关闭加密时设置 `Networking.Encryption.Mode=None`：直接发送 `28 字节 GWS1 头 + Protobuf 负载`。环境变量覆盖项为 `GAMESERVER_Networking__Encryption__Mode`，开启值为 `AesGcm`，关闭值为 `None`。开关在启动时读取，改动后重启服务端，客户端同步切换模式。

默认开启时必须配置有效通信密钥；密钥缺失或不合法直接阻止启动，不自动回退明文。关闭时不要求通信密钥。示例客户端同样默认 AES-GCM，可通过环境变量或 `--plain` / `--aes-gcm` 显式选择模式。

## 初始化与密钥

通信双方预先持有相同 32 字节通信主密钥，通过 `Networking.Encryption.KeyBase64` 配置。主密钥与 JWT 签名密钥分开；仅通信密钥需要配置在客户端。

服务端连接后发送固定 40 字节 hello：

| 偏移 | 字节数 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `TCPA` |
| 4 | 1 | 版本 `1` |
| 5 | 3 | 保留，全零 |
| 8 | 32 | 每个新连接独立随机 salt |

双方使用 HKDF-SHA256，主密钥为 IKM，以上 salt 为 salt，分别产生两个 32 字节方向密钥。info 为 UTF-8/ASCII `GameTcp/v1/client-to-server` 和 `GameTcp/v1/server-to-client`，不带结尾零字节。服务端发送使用 s2c，接收使用 c2s；客户端相反。

服务端只发送一次 hello，客户端收到后即可发第一个加密登录包，不需要额外往返协商。连接能否登录仍由 JWT 和账号验证决定。

## 逐包格式

GWS1 包头沿用 `PacketCodec` 的 v2 格式。头中的 `PayloadLength` 是加密前负载长度，整个可见包头作为 GCM 附加认证数据（AAD）。空心跳也有 16 字节标签。包大小上限包括标签，AES 模式的最大应用帧比明文模式少 16 字节。

发送和接收各自使用从 0 开始的 `uint64` 计数器，nonce 为 `4 个零字节 + 8 字节小端计数器`。TCP 有序传输，无需额外在线路上传输 nonce 或序号。每个方向每次成功编解码后计数器增加；达到上限关闭连接。同连接不可重置计数器或复用同一个方向密钥建立新连接。

接收顺序：校验帧长度 → 读完整帧 → 验证标签并原地解密 → 解析 Protobuf → 业务分发。认证失败直接关闭连接，不尝试换密钥或回退明文。并发发送在同一发送锁内编码和写完整帧，确保计数器与线上顺序一致。

相关实现为 `PacketCipher`、`ConnectionCipherFactory`、`TcpPacketReader`、`TcpConnection`。协议层具有独立 Python cryptography 生成的已知向量测试，以及篡改、错误密钥、重复包、跨连接重放、方向反射、边界长度和并发发送测试。

## 使用范围

这是预共享密钥通信方案：客户端内置密钥可能被逆向提取，不提供证书身份认证和前向保密，已知通信主密钥并记录 salt 的人能够解密历史流量。需要这些属性时应选择经过审计的安全传输方案。包头未加密但被认证，路由号和长度对旁观者可见。

.NET 的 AES-GCM 在 Linux 可使用 OpenSSL 加密原语，这与创建 `SslStream`、证书上下文和 TLS 记录缓冲区不同。本项目移除了游戏连接的 TLS 实现，但不禁止底层密码库提供 AES 算法。
